# Ledger

Four lists: claims we may publish, departures from ePrint 2026/443, the rulings the signer is built under, and open obligations. Status is **Ran** (executed, output committed), **Derived** (argued, not machine-checked) or **Open**; and, from signer stage 1a, **Read** (read in a pinned source at the place named, not executed) and **Executed, not committed** (computed once by an uncommitted script, and owed as a committed test by the stage named; stage 1b paid what stage 1a owed, and no row carries the label now). Update a row in the same PR that changes its evidence.

## Departures from the paper

| # | Paper | Here | Why | Decided |
| --- | --- | --- | --- | --- |
| D1 | Verifier repeats the hash-to-prime search. | The search variable is carried: first an index, now a salt. | Constant verifier cost; then collision replay. | 11-07, 11-12 |
| D2 | Chain length equals the torsion exponent `e`. | Chain length `e′ = e − 2`; signature points keep order `2^e`. | The two theta structures cannot otherwise be identified. | 11-09, 11-10 |
| D3 | Step 8 on a basis of `E_vk[p+1]`. | Step 8 on `E_vk[2^e]`, both components, three points. | Sufficient once the chain is two short; removes a search and a failure mode. | 11-10 |
| D4 | §5 verifier described without pairings. | One Weil pairing identity before the chains. | A non-isotropic kernel does not stop a chain. | 11-11 |
| D5 | No canonical form for `E_sig`. | Least Montgomery coefficient of the class, plus a sign rule. | Strong unforgeability needs one encoding per signature. | 11-10 |
| D6 | Identification of the midpoint structures not specified. | Dual structures from closed-form matrices. | Had to be supplied. | 11-10, 11-11 |
| D7 | Primality test unspecified. | Deterministic Baillie–PSW on one degree. | A consensus verifier cannot use random bases. Open, see O1. | — |
| D8 | Salt uniformly random. | Salt derived from seed, public key, message, counter and caller randomness. | No dependence on the random number generator; auditable when the randomness is zero. | 11-12 |
| D9 | Public key with basis hints (C reference). | Public key is the Montgomery coefficient alone. | Smaller key; the basis is derived. | 11-08 |
| D10 | — | The starting curve `A = 0` is refused as a key. | Its endomorphism ring is public. | 11-08 |
| D11 | Reference key generation as shipped. | Exporter build rejects a non-positive Cornacchia cofactor. | C9. | 11-11 |
| D12 | Salt of `2λ` bits, `λ` the security parameter of the level. | D13 | No parameter-set identifier. | A set identifier in key and signature containers and in the message the caller supplies; the challenge transcript is unchanged. | D14 | Does not say how an implementation is laid out. | The committed test vectors are one public crate, `prism-vectors`, with a documented reader for each family of data; it depends on the field crate alone. The verifier's public API carries no test data and no parser for it (`prism_verify::reference` is removed), and no build of the three library crates contains the vectors crate. The operation counter and the verifier's stage names are measuring equipment and not library: `prism_field::ops` and `prism_verify::stage` exist only with the `op-count` feature, which no manifest enables, and a default build has neither in its API or its documentation (library part 2). The interface is one front crate, `shekyl-prism`: a public key and a signature are typed values that carry their parameter set and are valid by construction, the three layer crates are re-exported under its `hazmat` module with no promise of stability, and the byte-level `prism_verify::verify` stays as the low-level entry and the regression anchor (library part 3; C13). The layer crates take the documentation standard one crate at a time. `prism-field` is the first: it denies missing documentation with and without the counter's feature, its documentation is built in CI with warnings denied, and its public surface is what was decided and not what was inherited, 106 items where it had 547.
