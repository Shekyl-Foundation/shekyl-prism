# Ledger

Four lists: claims we may publish, departures from ePrint 2026/443, the rulings the signer is built under, and open obligations. Status is **Ran** (executed, output committed), **Derived** (argued, not machine-checked) or **Open**; and, from signer stage 1a, **Read** (read in a pinned source at the place named, not executed) and **Executed, not committed** (computed once by an uncommitted script, and owed as a committed test by the stage named). Update a row in the same PR that changes its evidence.

## Departures from the paper

| # | Paper | Here | Why | Decided |
| --- | --- | --- | --- | --- |
| D1 | Verifier repeats the hash-to-prime search. | The search variable is carried: first an index, now a salt. | Constant verifier cost; then collision replay. | 11-07, 11-12 |
| D2 | Chain length equals the torsion exponent `e`. | Chain length `e′ = e − 2`; signature points keep order `2^e`. | The two theta structures cannot otherwise be identified. | 11-09, 11-10 |
| D3 | Step 8 on a basis of `E_vk[p+1]`. | Step 8 on `E_vk[2^e]`, both components, three points. | Sufficient once the chain is two short; removes a search and a failure mode. | 11-10 |
| D4 | §5 verifier described without pairings. | One Weil pairing identity before the chains. | A non-isotropic kernel does not stop a chain. | 11-11 |
| D5 | No canonical form for `E_sig`. | Least Montgomery coefficient of the class, plus a sign rule. | Strong unforgeability needs one encoding per signature. | 11-10 |
| D6 | Identification of the midpoint structures not specified. | Dual structures from closed-form matrices. | Had to be supplied. | 11-10, 11-11 |
| D7 | Primality test unspecified. | Deterministic Baillie–PSW on one degree. | A consensus verifier cannot use random bases. Open, see O1. | — |
| D8 | Salt uniformly random. | Salt derived from seed, public key, message, counter and caller randomness. | No dependence on the random number generator; auditable when the randomness is zero. | 11-12 |
| D9 | Public key with basis hints (C reference). | Public key is the Montgomery coefficient alone. | Smaller key; the basis is derived. | 11-08 |
| D10 | — | The starting curve `A = 0` is refused as a key. | Its endomorphism ring is public. | 11-08 |
| D11 | Reference key generation as shipped. | Exporter build rejects a non-positive Cornacchia cofactor. | C9. | 11-11 |
| D12 | Salt of `2λ` bits, `λ` the security parameter of the level. The basis search stopped at `2λ` candidates. | Salt of `e` rounded up to a multiple of 128 bits, and the same rounding as the candidate limit. The three built sets keep 32, 48 and 64 salt bytes and 256, 384 and 512 candidates, which both rules give; the rule fixes `p324` at 48 bytes and 384 candidates and `p664` at 96 bytes and 768. | The level is an assessment that moves and is not coded; the salt length and the search limit must be a property of the prime. | 11-14 (ruled; `p324` and `p664` are built with these values) |
| D13 | No parameter-set identifier. | A set identifier in key and signature containers and in the message the caller supplies; the challenge transcript is unchanged. Built in the front crate: `SetId` is `(e, f)` of `p = f·2^e − 1`, `e` then `f`, each a little-endian 16-bit integer, four bytes, and a value of it names one of the five built sets. A tagged key is `SetId ‖ bare key` and a tagged signature `SetId ‖ bare signature`, each exactly that length. `AcceptList` is the consumer's policy, made from sets written one by one, with no default and no list of every set; `verify_tagged` refuses on the identifiers and the list before any arithmetic and then runs the byte-level entry on the bare parts (C14). | A key or signature of one set must not be presented under another; the transcript already absorbs the public key, whose length differs per prime. With the identifier outside the transcript, that difference of lengths is what refuses a retagged key and signature, and it is an obligation on any set added later (O16). | 11-14 (ruled), 11-17 (built, library part 4) |
| D14 | Does not say how an implementation is laid out. | The committed test vectors are one public crate, `prism-vectors`, with a documented reader for each family of data; it depends on the field crate alone. The verifier's public API carries no test data and no parser for it (`prism_verify::reference` is removed), and no build of the three library crates contains the vectors crate. The operation counter and the verifier's stage names are measuring equipment and not library: `prism_field::ops` and `prism_verify::stage` exist only with the `op-count` feature, which no manifest enables, and a default build has neither in its API or its documentation (library part 2). The interface is one front crate, `shekyl-prism`: a public key and a signature are typed values that carry their parameter set and are valid by construction, the three layer crates are re-exported under its `hazmat` module with no promise of stability, and the byte-level `prism_verify::verify` stays as the low-level entry and the regression anchor (library part 3; C13). Test inputs are a library too: `prism-testkit` builds the negatives derived from the committed vectors and the responses made from public data, depends on the layer crates and the vectors crate, and is unpublished. A test lives in the lowest crate that contains everything it exercises, and no dependency edge points up, dev edges included: the tests that run both entries are in the front crate, and `prism-verify`'s own tests need nothing above it (library part 3b; `scripts/ci/check_no_upward_edge.py`). The interface also serves a caller that learns the set from the bytes: the identifier, the tagged containers and the accept list of D13 are in the front crate, built on the verifier's run-time name for a set and adding nothing to the layer crates; the interface has no item that yields every set (library part 4). A typed key is usable and not only well-formed: every check that depends on the key alone runs when it is built, the test of its basis included, and the key holds what was tested (library part 4b; O18). The layer crates take the documentation standard one crate at a time. `prism-field` is the first: it denies missing documentation with and without the counter's feature, its documentation is built in CI with warnings denied, and its public surface is what was decided and not what was inherited, 106 items where it had 547. The types the outside field library generates are private, and a set's two fields are the crate's own types with the operations of `Field` and no others (library part 5a; C16). `prism-isogeny` is the second: it denies missing documentation with and without its `oracle` feature, each public item says what it assumes, what it returns when the assumption fails and which check in the verifier establishes it, the crate documentation is a map of the path one verification takes, and the surface is 113 items where it had 208. The (2,2) step and the splitting are private modules, and the 2-isogeny model no caller used is a public, documented module under the `oracle` feature, kept for a researcher who wants to use or check it and absent from a default build: 134 items with the feature (library part 5b; C18). `prism-verify` is the third and last: it denies missing documentation in its three feature sets, its crate documentation has every refusal of the byte-level entry as a row of one table, in order, with whether the sender chooses the step's cost and which rows the tests reach, each variant of `VerifyError` lists the checks that give it in both entries, and each function that is a step says what it assumes and which call establishes it. An item has one path, its module's: the root keeps `verify` and `VerifyError`, and the thirty-odd root re-exports are gone (library part 5c; C19). With it the five parts of the library design round are complete. | Two goals: a reference other researchers can use and extend, and a complete implementation for Shekyl. Researchers want the vectors without taking a verifier, and a verifier's API should not carry test data. | 11-16 (ruled; parts 1 to 3 built), 11-17 (part 3b ruled and built; part 4 built), 11-19 (part 4b ruled and built; parts 5a and 5b built), 11-20 (part 5c built; the round's five parts complete) |
| D15 | Baillie–PSW as usually stated tests the integer for a perfect square before the Lucas leg, because no discriminant with Jacobi symbol −1 exists for a square and an unbounded search for one does not end. | No square test. The search for the discriminant is counted, 256 candidates, and an integer for which none has symbol −1 is refused as composite; the symbol modulo a square is never −1, so every square is refused there. A challenge degree is 7 modulo 8 and never a square, so the case does not arise in verification. | One refusal for squares where there were two, and no loop that ends on a computed value. A test holds that a square is refused by the Lucas leg (`a_perfect_square_is_refused_by_the_lucas_half`). The verdict on every integer is unchanged: 24,000 degrees before and after, and the differential run against sympy. | 11-19 |
